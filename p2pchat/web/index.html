第 1 步 · 先找到彼此

连接服务器

服务器只帮你们找到同房间的人；文字、图片、文件和录音只在你们两台设备之间直传。

点击连接即确认这个服务器，并自动汇集不含聊天内容的诊断记录；可在设置里暂停。

默认请用加密的 wss://。明文 ws:// 只在你主动勾选确认后的这次会话里放行；连上之后勾选会自动复位，不会变成「以后总是允许」，也不会对别的服务器生效。
明文信令可以被同一路径上的其他人观察、篡改或切断：例如注入错误的连接候选让直连失败、伪造房间事件。它只适合你确实在可信网络、又连不上加密端点的场合，不作为推荐方式。
加入房间用的是服务器下发的一次性 nonce + 派生值证明，房间密钥不上链路；但明文内容仍可被观察与篡改，所以不要把明文当成安全链路。

第 2 步 · 逐个试哪条路能直连

正在寻找能直接连通的路

连接后自动开始。

    顺序是固定的：先试基础方式，再试需要额外条件的方式。列表顺序不代表先后启动 —— 所有可用方式同时尝试，第一条能聊天的连接成功就自动进入聊天，其余方式继续在后台尝试。每一种都写清「是什么、靠什么打通、什么网络可行、失败最常见的原因」。

    直连不成就是失败：这里没有任何中继、TURN 或服务器代传的选项，也不会偷偷改走服务器。UDP 探测只探测、不传内容；STUN 只观察地址、不是中继。

    状态词怎么看
    等待中
    还没轮到它，或正在排队。
    尝试中
    正在探测，通常几秒内出结果。
    已打通
    这条路径成功了，可以用来聊天。
    已观测
    只用于探测或观测的方式成功了；它不能传消息，所以不叫「已打通」（只有 UDP 探测和 STUN 映射观测会用到）。
    不可用
    试过但失败了；点开这一条可以看到人话原因。
    不支持
    当前平台或当前配置用不了（例如安卓上的路由器放行）。

    房间成员 0

    群发会分别直连每个人；未打通的连接不能发送。

    剩余方式

    还没尝试、或还没成功的方式。按固定顺序列出，实际是并行尝试。

      可用性

      每一种方式在当前平台上是否能用：可用 / 不可用 / 不支持。「可用」只说明本机支持这种方式，不代表已经打通。

        延迟与测速

        延迟是本机计时的往返探测结果，尚未测到的显示「尚未测得」，不用零代替。测速在独立通道上跑，标注的是应用层速度，不是线路带宽。

        尚未测速。最多发送 5 秒或 32 MiB；以对方确认接收的数据计算有效速度，不等于运营商带宽。

          本机支持哪些功能

          浏览器和 Android 默认只支持浏览器直连。桌面原生组件需单独可用。Python 回声节点仅支持浏览器直连；QUIC / TCP 要找同样支持的客户端。桌面组件默认只绑定本机地址，跨设备前需由操作者配置绑定地址。

          路由器入口申请（第 9 条「路由器放行」）只在桌面 Python 侧提供，必须显式授权；安卓显示为「不支持」，网页版也不会有自动修改路由器的开关。

          诊断记录与导出

          默认自动汇集诊断元数据，可暂停。

          不含正文、密码、媒体、完整地址或连接密钥。记录在本机保留最多 7 天 / 20 MiB，待补传最多 2000 条；清除应用数据会丢失。只有中心确认保存后才移出待传队列。

          
 
          安全与测量边界
          房间密码用于双方配对，但不能防范知道密码的恶意成员冒充。公网服务器连接必须加密。没有中继、也没有服务器代传选项：找不到直连就明确失败，绝不会改走服务器转发聊天。上面三种地址选择方式属于同一个 WebRTC 协议，并非三个打洞协议。延迟由本机计时的往返探测得出，不把两台设备的时钟差当延迟。测速使用独立通道但仍共享网络带宽，可能影响聊天。这里不声称任何一次本机试验或浏览器模拟已经证明真实家庭宽带可用。
