# 打洞方式说明（人话版）

这份文档是界面文案的唯一来源。**网页版和桌面版必须使用这里的名称与解释**，不要各写一套，也不要把内部代号（如 `ice-v6`、`tcp-simopen`）直接摆在用户面前当标题。

## 一句话总原则

所有方式的目标都是**让你的两台设备直接对话，不经过任何服务器中转**。
尝试顺序是固定的：**基础方式在前，需要额外条件的在后**。任何一种成功，就立刻可以聊天；**其余方式仍在后台继续尝试**，成功后可以随时切换到更优的那条。

## 九种方式

| 序号 | 界面名称 | 它到底是什么 | 什么网络下可行 | 失败最常见的原因 | 能否传消息 |
|---|---|---|---|---|
| 1 | **双栈直连** | 同时用 IPv6 和 IPv4 两种地址去找对方，谁先通就用谁 | 双方都有可用公网地址（大多数家宽） | 两边 NAT 都严格、或运营商拦截 UDP | 是 |
| 2 | **IPv6 直连** | 只用 IPv6 地址直连 | 两台设备都有可用公网 IPv6，且入站防火墙放行 | 一方没有 IPv6；或路由器/防火墙挡了入站 | 是 |
| 3 | **IPv4 直连** | 只用 IPv4 地址直连 | 至少一方有公网 IPv4，或双方 NAT 容易打洞 | 双方都在大内网/CGNAT 后面 | 是 |
| 4 | **UDP 探测** | 互相发加密小包，确认「这个地址端口能不能直达」 | 只要能出去 UDP 就能探测 | UDP 被运营商限制 | 否，只能探测 |
| 5 | **QUIC 加密直连** | 用同一个 UDP 端口建立一条加密通道来传数据 | 双方 UDP 可达 | UDP 被挡；或中间设备干扰 | 是 |
| 6 | **TCP 加密直连** | 用 TCP 建立一条互相验证身份的加密连接 | UDP 被限制但 TCP 能出去的网络 | 一方无法被动接受连接 | 是 |
| 7 | **TCP 同时打开** | 双方**同时**主动向对方发起连接，谁都不当「服务器」 | 只允许主动外连、不允许被动监听的网络 | 双方时序错开，或中间设备重置连接 | 是 |
| 8 | **STUN 映射观测** | 问外网「我在你眼里是什么地址和端口」，用来判断能不能直连；它不是中继，只观察地址，不转发任何数据 | 所有能上网的环境 | 服务器不可达；对称 NAT 下观测结果无用 | 否，只能观测 |
| 9 | **路由器放行（自动开一个端口）** | 向你自己家的路由器申请开一个端口 | 路由器支持该协议且已开启 | 路由器关闭了这类功能；运营商光猫拦截 | 否，它只开端口 |


> 第 9 项在协议层使用 UPnP IGD、PCP、NAT-PMP 与 IPv6 防火墙放行；这些缩写只出现在技术详情里，不作为界面标题。它本身不传数据，只是让别的直连方式能进来。

## 三条必须讲清楚的限制

1. **UDP 探测（第 4 项）只能确认能不能直连，不能用来收发消息。** 界面上必须标注「仅探测，不传内容」，不要让用户以为它通了就能聊天。
2. **STUN（第 8 项）也不是中继。** 它只观察地址，不转发任何数据。整个产品**没有中继、没有 TURN，也不通过服务器转发聊天**；直连不成功就是失败，不会偷偷改走服务器。
3. **路由器放行（第 9 项）默认关闭，必须用户明确同意才会尝试**，并且当前**只有桌面 Python 版支持**，安卓版显示为「不支持」。

## 状态用词（界面统一使用）

| 状态 | 含义 |
|---|---|
| 等待中 | 还没轮到它，或正在排队 |
| 尝试中 | 正在探测，通常几秒内出结果 |
| 已打通 | 这条路径成功了，可以用来聊天 |
| 已观测 | 只用于探测或观测的方式成功了（只有 UDP 探测和 STUN 映射观测会用到）。它不能传消息，所以不叫「已打通」，也不代表能聊天 |
| 不可用 | 试过但失败了；鼠标悬停/点开可以看到人话原因 |
| 不支持 | 当前平台或当前配置用不了（例如安卓上的路由器放行） |

说明：只有能聊天的路径才允许显示「已打通」；UDP 探测和 STUN 映射观测不属于聊天路径，成功时显示「已观测」并在同一行标注「仅探测，不传内容」。界面上的任何状态都不允许把没试过、失败或未确认的路径说成成功。

## 设置面板里应该看到什么

- **剩余方式**：还没尝试、或还没成功的方式列表
- **可用性**：每种方式是「可用 / 不可用 / 不支持」
- **延迟**：已打通方式的实测往返时间
- **测速**：一个可手动触发的按钮，在独立通道上测，并明确标注「这是应用层速度，不是线路带宽」
