How LGPL compliance is kept
---------------------------
1. **Dynamic linking only.** The application is Python; the Qt libraries
   (``libQt6Core.so.6``, ``libQt6Gui.so.6``, ``libQt6Widgets.so.6`` …) and the
   PySide6/shiboken6 extension modules stay as separate shared objects inside the
   bundle (``_internal/PySide6/Qt/lib``, ``_internal/PySide6/*.so``). Nothing is
   statically linked, wrapped or re-licensed.
2. **Unmodified libraries.** The bundled Qt/PySide6 binaries are byte-identical
   to the published wheels above; the build never patches them. Replacing them
   with the same SONAME versions is enough to relink, which is the practical
   form of the LGPL's "reverse engineering for debugging" allowance here.
3. **License texts travel with the package.** ``licenses/LGPL-3.0.txt`` and
   ``licenses/GPL-3.0.txt`` (LGPL-3.0 incorporates the GPL-3.0 terms by
   reference) are copied into the bundle by ``p2pchat/tools/desktop.spec`` and
   also live in the source tree under ``p2pchat/python_desktop/licenses/``.
4. **Source availability.** Qt sources come from the Qt Project
   (https://code.qt.io/), PySide6/shiboken6 sources from
   https://code.qt.io/cgit/pyside/pyside-setup.git/; this product's own source is
   shipped in the same repository.
5. No Qt WebEngine, Qt Quick/WebEngine modules, commercial Qt components or
   static plugins are used; only QtCore/QtGui/QtWidgets are imported (see
   ``p2pchat/python_desktop/qt_ui.py``).
