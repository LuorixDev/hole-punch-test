# P2P Lab：两人 IPv4 / IPv6 打洞实验与终端聊天

Python 3.12+，当前以 Linux 为正式验证平台。服务器提供 **IPv4 信令、STUN、TCP 映射观察、中心日志**，不提供 TURN，也不转发聊天、图片、文件、ping 或测速数据。

源码以 MIT 许可证开源，第三方组件保留各自许可证，见 `THIRD-PARTY-NOTICES.md`。Windows x64 / Linux x64 单文件客户端和服务端从本仓库 GitHub Releases 下载，不需要安装 Python。Linux 需要 glibc 2.35+（Ubuntu 22.04+ 或同等发行版），不支持 Alpine/musl；下载后先执行 `chmod +x P2PLab-*linux-x64`。Windows 使用终端运行 `.exe`，程序未签名，SmartScreen 可能提示。

GitHub Actions 在各自原生系统中使用 Python 3.12.15 构建：先运行源码回归，再验证单文件程序之间的聊天、ping、双向测速和中心日志。推送 `v*` 标签后，仅当两端构建与检查全部通过才公开 Release，附带 SHA-256、构建记录和第三方许可/源码。`workflow_dispatch` 仅构建供检查；发布新版本需推送新标签。CI 通过不等于跨运营商公网打洞成功。

客户端直接启动后，在 TUI 填写服务器地址和房间号；第一人创建房间等待，第二人加入后自动开始全部实验。第三人被拒绝。先跑原始网络测试，再主动尝试路由器放行；成功一种不会取消其余测试。

## 本机运行

从源码运行时，在项目目录建立环境并安装依赖：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
```

终端一，启动服务器：

```bash
.venv/bin/python server.py --host 127.0.0.1
```

终端二、三，分别运行客户端，然后输入相同房间号：

```bash
.venv/bin/python client.py --config configs/loopback.toml --loopback --name A --data data/client-a
.venv/bin/python client.py --config configs/loopback.toml --loopback --name B --data data/client-b
```

也可加 `--room 1001` 跳过房间输入。本机多实例必须使用不同 `--data`，不能共享设备身份和队列。不要把 `--loopback` 用于跨设备测试。

### 中文 TUI

安装依赖后，直接启动即可，无需配置文件或命令行参数；使用系统 Python 时，入口会自动使用项目内已安装好的 `.venv`，无需手动激活：

```bash
python client.py
```

加入页只需填写服务器和房间号。服务器支持 `IP:端口`、域名或完整 `ws://` / `wss://` 地址；省略协议时使用明文 WS，省略端口时使用 8443，省略路径时补 `/ws`。完整 URL 保留协议默认端口和自定义路径，`http://` / `https://` 自动转换为 WS / WSS。IPv6 带端口时写 `[IPv6]:端口`。明文连接显示警告，不再需要额外传 `--allow-insecure`；这仅适用于界面中主动填写地址的流程，原 CLI 安全检查不变。

默认不需要入房密码，服务端不传 `--token-file` 即可；导出中心日志的管理密钥独立保留，不是入房密码。配置文件仍可预填服务器和设置高级实验参数，不会被界面覆盖写入。

交互终端默认启动全屏中文界面；不指定 `--room` 时显示加入页。可用 `--tui` 显式选择 TUI，或 `--plain` 保留逐行终端输出。输入/输出被管道重定向时默认使用逐行模式，原有 CLI 自动化不变。

- **聊天**：P2P 消息、信令/对端状态、当前链路、矩阵进度、待上传日志数，以及 RTT、上下行确认吞吐。
- **传输**：图片/文件的进度、接收回执、保存位置及接收、拒收、取消和查看操作。
- **顶部地址**：本机和对端的 IPv4 本地/出口观察地址、IPv6 稳定/临时地址和 HTTP 入站证据，每端每族各占一行。HTTP 回连超时只显示“未确认”，不判定防火墙必然阻止。超长地址清单省略显示，悬停顶部可看完整清单，网络页保留完整证据。
- **IPv4 NAT 等级**：矩阵期间读取真实 UDP/STUN 同 socket 映射和独立 RFC 5780 过滤探测，顶部显示本机与对端的 NAT1–NAT4 或“证据不足”。仅当探测点给出足够证据时分类；过滤超时可能受丢包影响。IPv6 不套用 IPv4 NAT 等级。
- **打洞矩阵**：每次尝试的地址族、重试档、请求/实际报文大小、两端结果和耗时；“原因”前的“方案解释”用中文区分 IPv6 状态防火墙打洞、IPv4 NAT 打洞、TCP 直连/同时打开、WebRTC 和各类网关放行。选中记录按 Enter 查看完整解释、全部参数与原始结果。
- **网络**：完整网卡地址清单、稳定/临时地址、状态、剩余寿命、入选/排除原因、MTU、IPv6 HTTP 回连、公共 IP 查询和网关。
- **链路**：已认证/冷备/已关闭通道、当前通道、验证 RTT、样本年龄和每条链路的上下行结果；可切换链路或批量测速。持续 RTT 默认关闭，可显式勾选“当前链路实时 RTT”：仅该页可见、且未测速时每约 2 秒测当前链路，不轮询备用链路。旧样本标为历史，不冒充当前延迟。
- **完整日志**：关键字、级别、本次/全部历史筛选；每页 100 条，可翻到更早记录、返回实时，详情保留全部原始 JSON。大事件的持久分片自动重组。
- **参数**：只读展示实际生效的配置、观察点、地址预算、超时和所有重试参数；不把未生效的界面值冒充运行参数。

操作栏和消息输入框只出现在聊天页，不占用打洞、网络、链路、日志和参数页。聊天页保留测延迟、双向测速、重测网络、重新打洞和退出；链路页使用“批量测速”，依次测试已验证方案的两个方向，冷备方案逐条重建、测完释放，不更改健康的聊天所选通道，一条失败后继续下一条，逐条显示结果与总体进度。测速可选 1–1024 MiB，低于一秒的结果标为短样本，失败后保留的历史方向结果标为旧值。

双方记录完整打洞结果后，闲置备用链路立即进入冷备：释放套接字、后端任务/定时器及该尝试的网关租约，但保留方案参数、成功证据和历史测量。切换链路或批量测速时协调端分配新尝试 ID，双方按原参数重新打洞、认证并验证数据通道；重建可能失败，不把历史成功伪装成现有连接。需要信令在线、双方客户端和服务端支持 `cold-path-v1`，旧版本未协商时不主动销毁备用通道。聊天/文件/测速中的通道不清理；临时测速通道异常无人使用 30 秒后回收。正常完成矩阵后通常只保留一个主通道，矩阵当前尝试和按需重建会临时增加资源占用，单个端口阵列实验仍可能申请其预算内的多个端口。

每个客户端只有一个统一维护任务，不为每条链路单独启动 RTT/保活循环。主通道只有闲置约 12 秒才做一次不计 RTT 的存活检查，业务流量正常时不额外探测。测速期间暂停额外 RTT 测量，但测试其他冷备方案时仍保留闲置主通道的最低限度保活，避免长批次测速让聊天主通道过期；这不保证所有设备的 NAT/防火墙状态都能长期维持。主通道失效后使用时最多按需尝试三个已验证方案重建；没有可重建方案时仍按原策略记录故障/重试。已有历史日志不删除，停止的是未请求的重复测量。

原有 `/ping`、`/speed` 等命令仍可输入。Ctrl+1 至 Ctrl+6 切换原有页签，Ctrl+7 切换传输页，Ctrl+L 返回聊天并聚焦输入，Ctrl+Q 退出；详情支持中文字段名和原始 JSON 两种视图，Esc 关闭。窄终端自动收拢布局，表格可横向滚动。

界面展示不会代替或截断 SQLite 日志，也不改变中心日志上传/确认机制。聊天正文仍只走 P2P，不写进服务端诊断日志。退出先释放链路与网关租约、有限等待日志确认，未确认记录继续保留在本地。

### 外网部署检查

公网 IP 查询同时尝试 ipify、AWS、icanhazip 和 IPW 的 IPv4 / IPv6 HTTPS 接口。每个请求独立限时 3.5 秒、最多读取 512 字节，不跟随重定向，不采用代理环境变量；仅接收对应地址族的公网 IP。接口超时、DNS 错误、封锁页、私网地址和异常响应均记录原始原因，不把查询失败变成启动异常，也不伪造地址。

HTTP 查询得到的是该 HTTP 请求的出口地址，不是 UDP NAT 映射。系统级 VPN / TUN 仍可能接管流量；禁用代理环境变量不能绕过 TUN。真实外网测试还必须观察交换服务器和 STUN 的映射证据、两端新建 P2P 通道的认证结果。没有全局 IPv6 地址、服务器没有 IPv6 出口或回连超时，均不能当作已确认的入站防火墙结论。

服务器默认只开放同一个端口号的 **8443/TCP 和 8443/UDP**；测试 IPv6 回连时，服务器自身需要可用的 IPv6 路由。正常实验中的接口失败、方案不适用、打洞失败与客户端启动/后台异常是不同事件，中心日志全部保留。

### Windows 控制台打包

已加入 Windows x64 / Python 3.12 的构建配方；必须在 Windows 构建，不能把 Linux 生成的文件当成 Windows exe。当前工作区核验了 36 个锁定依赖的 Windows wheel、模拟 Windows 分支及 Linux 冻结运行；**Windows 实机与跨运营商网络验收尚未完成**。

在 Windows 安装 Python 3.12 x64 后，在项目目录的 PowerShell 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_windows.ps1
```

脚本安装锁定依赖，使用 MSYS2 UCRT64 构建原生库，运行 Windows 地址读取/启动及原生传输测试，再校验安装固定版本 LibreSpeed CLI、构建客户端和服务端单文件程序并实测聊天/ping/测速/日志。成功后生成 `dist/release/P2PLab-Client-windows-x64.exe` 和 `P2PLab-Server-windows-x64.exe`；使用发布包不需要另装 Python 或 MSYS2。保留控制台是 TUI 的要求，不使用隐藏控制台的 `--windowed` 模式。脚本中的进程级执行策略只用于运行该构建脚本，不更改系统级设置。

Linux 可在 Python 3.12 x64 环境中安装 `packaging/build-requirements.txt` 后运行 `python tools/build_release.py`。脚本使用 `packaging/client.spec`、`packaging/server.spec` 的 one-file 模式，输出 `dist/release`；运行时会解压内嵌依赖到临时目录，因此需要可写、可执行的临时目录。客户端内嵌 LibreSpeed，不要求朋友另装测速程序。源码版本仍支持从 PATH 或配置覆盖测速程序。Linux CI 在项目目录构建固定版本 libnice 0.1.22 与 libutp 并内嵌，不修改系统库；原始报文实验仍需权限，不自动提权。手动构建发布包必须先运行 `tools/install_libnice.py`、`tools/install_libutp.py`；前者需要 Meson、Ninja、GLib/GnuTLS 开发包及 C 编译器。发布脚本会拒绝缺少原生库的客户端包；直接运行源码时，缺失的可选后端仍显示不适用。

冻结版默认将身份、离线队列和压缩日志保存在 `%LOCALAPPDATA%\P2PLab\client`（macOS 为 `~/Library/Application Support/P2PLab/client`，显式设置的 `XDG_DATA_HOME` 仍然优先），不写到 exe 的依赖目录；高级配置可放到 exe 同目录的 `client.local.toml`。同机多实例仍须指定不同 `--data`，设备目录锁在 Windows 也生效。

Windows 用只读 PowerShell JSON 获取网卡地址、DAD 状态、寿命和默认路由。随机 IPv6 后缀不足以确认临时/稳定隐私地址，界面标为“类型未确认”，但已确认可用状态的地址仍参与实验；未确认状态、DAD 未完成、重复、过期、网卡关闭或 `SkipAsSource` 地址不参与建链。PowerShell 不可用时保留降级证据，不猜测 IPv6 状态。

Windows Actions 现在从固定提交构建 libnice/libutp，收集传递 DLL 依赖并内嵌到单文件客户端。构建会强制运行原生后端 IPv4/IPv6 聊天、文件校验和双向测速，再在打包后的 exe 中重复验证，结果写入 `build-record-windows-x64.json` 的 `native_smoke`。这仅验证本机回环，不代表广域网千兆性能或跨运营商连通率。Linux 原始报文实验、SO_REUSEPORT 同端口竞争和 timerfd 不能靠 Windows 编译获得；缺失能力仍明确记录不适用。防火墙放行与真实 IPv6 入站仍需在朋友的 Windows 网络上确认；程序不会自动关闭系统防火墙。

Windows 手动原生构建需 MSYS2 UCRT64，安装 `mingw-w64-ucrt-x86_64-{gcc,meson,ninja,pkgconf,glib2,gnutls}` 后运行 `tools/build_windows.ps1`；非默认安装目录使用 `-Msys2Root` 指定。源码客户端也会优先加载这些构建出的 DLL，不要求修改系统 PATH。

聊天侧栏用 `#001 IPv6 QUIC打洞` 等编号与昵称关联矩阵、链路和日志；原始尝试 ID 仍保留在完整日志/详情。侧栏保留最近 1000 条事件的原始文本，在隐藏期间不按零宽度渲染，切回或调整窗口宽度后重新排版；超出该范围的事件仍可从持久完整日志查询。聊天历史不会因切换页签而清空。

### 公网测速和双端参考上限

采用开源、独立 Go 进程的 LibreSpeed CLI；不会经交换服务器转发测速流量。当前机器已安装到项目 `.tools`；另一台 Linux x86_64/arm64 机器可用固定版本和 SHA-256 校验安装（不需要 root）：

```bash
.venv/bin/python tools/install_librespeed.py
```

也可自行安装 `librespeed-cli` 到 PATH，或在 `[wan]` 中指定 `executable`。源码及 LGPLv3 许可证见 LibreSpeed 官方 `librespeed/speedtest-cli` 项目；项目内安装会保留 `.tools/LIBRESPEED-LICENSE`。

启用外部诊断的真实网络中默认在启动时测速；关闭 `[wan].enabled`、关闭 `experiment.diagnostics` 或使用 `--loopback` 时不会执行。隔离虚拟网络不接入公网，因此显示未测试，而不是伪造带宽上限。测速在 IPv6 HTTP 入站基线之后、打洞矩阵之前执行，整体最多 150 秒，不阻止信令在线和日志上传。每个可用地址族绑定默认出口网卡的地址，从最多 64 个 HTTPS 节点中探测并选择最多两个；每节点每方向默认 8 秒、6 并发连接，保留各方向最佳实测结果。CLI 输出、节点失败和全部样本持续上传中心日志；子进程超时/取消会终止并回收。缺少测速程序、IPv6 节点列表不可达等情况会明确记录未测试/失败。

**这会产生大量公网流量，不适合计费/受限连接**。千兆链路每方向 8 秒、两个节点、两个地址族，理论上可以累计数 GB 流量；可降低节点数/时长或完全关闭。默认不会分享结果到 LibreSpeed 遥测服务，不使用代理环境变量，不关闭 HTTPS 证书验证。

链路页“公网测速”或 `/wan` 可以重测。它与本机 P2P 测速互斥，启动期间链路测速控件禁用。参考按地址族和相同网卡匹配；ICE 选路未知时不猜测。上行参考是 `min(本机 WAN 上行, 对端 WAN 下行)`，下行反向计算。双方数据通过严格限定字段的诊断信令交换，不允许用该消息转发聊天。超过 30 分钟的参考、缺失的方向、换网卡/出口后的样本、不到一秒的 P2P 短样本和旧测速轮次都不标达标。

达到双端参考 90% 时标记 `≥90%参考`，不称为理论上限。超过参考 120% 则标“超过 WAN 参考”，可能是局域网、路由差异或公网节点低估。知道真实套餐上限时，可分别在两台机器 `[wan]` 配置 `upload_mbps` / `download_mbps`；双方都使用配置上限时标 `≥90%上限`。测速服务器负载、跨网互联、Wi-Fi 和多连接/单连接差异均可能影响公网实测值，不能仅靠测速确认运营商的物理极限。

每次 `experiment.result` 也保存 `scheme_explanation`，随结果上传服务端。解释描述尝试机制，不把未测量的 NAT 类型当结论；UDP 认证探测成功、网关租约响应、可靠聊天通道验证分别展示。已经启动的进程需要退出后重启才会加载代码修改。

### 三个 Konsole 的隔离网络体验

Linux 桌面安装 `konsole`、`iproute2`、`util-linux`、`nftables`，并允许无特权 user/network namespaces 后，可以运行：

```bash
.venv/bin/python tools/interactive_lab.py start
```

脚本先实际验证两个 CLI 客户端的 P2P 聊天、ping、双向测速和中央日志，再打开三个独立 Konsole：server、client-a、client-b。两个客户端自动加入 `demo-1001`，直接输入聊天内容即可；可用 `/ping`、`/speed 1`、`/paths`、`/results`，实验成功后仍继续其余矩阵。

这是三个独立网络应用节点，不是三个 Python venv，也不是完整虚拟机；另有两个不可见的虚拟 CPE 命名空间，模拟 IPv4 NAT 和 IPv6 状态防火墙。共用项目文件系统，不用于隔离恶意代码。没有宿主网络上联；所有 veth、路由、sysctl 和 nftables 规则都只在新建命名空间内配置，宿主网络及防火墙不修改。

默认 `stateful` 模式下 IPv6 HTTP 回连可能超时，但双方出站 UDP 可建立状态并打洞；不要把 HTTP 回连失败当成所有 P2P 不可用。临时 IPv6 是内核根据 `mngtmpaddr/use_tempaddr` 实际生成的，客户端从真实虚拟网卡读取。实验使用 `2001:db9:*` 等合成地址，只存在于无上联的隔离网络，不代表分配给用户的公网地址。

模拟 CPE 不提供 UPnP/PCP/NAT-PMP 控制服务；交互客户端仍主动尝试这些方法，控制请求不支持/失败会明确记录，不能冒充真实网关兼容性通过。网络没有公网出口，因此关闭外部 IP 查询和公共 STUN，保留本机系统诊断及自有服务器观察点。

实验服务器的 HTTP/WS 仍监听 `0.0.0.0`，STUN 单独绑定 `198.51.100.1`，避免多网卡通配 UDP 回包选择与客户端请求不同的源地址。STUN 映射观察成功不等于 IPv4 NAT 打洞成功；以每条实验结果及实际认证数据通道为准。


查看命名空间、进程和当前状态：

### 图片、文件与消息统计

聊天页的“文件”“图片”打开路径选择窗口，也支持直接输入上述命令。传输页展示任务、字节进度、实时速度、平均速度、耗时、开始时间和接收时间，并提供接收、拒绝、取消、查看图片和接收目录操作。实时速度按最近约两秒的接收/确认字节估计；等待用户接收的时间不计入传输耗时，结束后耗时冻结。图片支持 PNG、JPEG、GIF、WebP、BMP 的文件标识检测，保存时采用与标识相符的扩展名；**终端不内嵌位图**，查看图片需 Linux 桌面的 `xdg-open` 与系统图片查看器。任意普通文件均可作为文件附件发送，接收后不会自动执行或打开。

默认自动接收，保存到对应客户端的 `<data_dir>/downloads`；可设置 `[transfer].download_dir`、`auto_accept = false`、`max_mib = 10240`。默认单文件上限 10 GiB，每端最多同时发送两份、接收两份；传输页保留最近 200 项记录，历史诊断仍在持久日志中。文件采用 ID 前缀避免同名覆盖，已存在的文件不会被覆盖。数据仅经已认证的 TLS/QUIC/DTLS P2P 通道：60 KiB 二进制块、4 MiB 未确认窗口、累计确认和磁盘背压、1 MiB 磁盘写入批次，以及最终 SHA-256 校验。QUIC/WebRTC 的独立批量流与控制流之间先等待全部字节确认，再提交结束校验，避免跨流乱序。断线、取消、磁盘错误或校验失败会终止传输并清理本轮 `.part` 文件，**暂不支持断点续传**，需重新发送。旧客户端不支持附件时明确报错。

每条已接收/已送达消息后展示灰色斜体标签与彩色斜体数字：接收完成时间、平均传输速度和接收耗时。发送端显示接收端回执中的同一时间与统计；接收时间使用接收端时钟，TUI 转为查看端本地时区。耗时使用接收端单调时钟，不相减两端墙钟。附件均速从准备就绪到完成写盘、校验和持久化，包括就绪回复、首块传输、网络与磁盘成本；短文本计时从接收端收到就绪请求到正文到达，包含就绪握手往返，因此**文本均速不是链路带宽**。旧对端无法提供统计时显示未测，不伪造速度。空文件速度为零。

附件开始、进度、结束、失败、字节数、保存路径、校验值和回执均持续记录并上传中央日志，进度日志最多每秒一次加末次更新；正文和附件内容不进入日志，也不通过服务器中继。

测速是接收端确认的应用层有效吞吐，不是运营商标称带宽。双方在签名握手中协商二进制测速能力：60 KiB 数据块、不使用 Base64/JSON 包裹载荷、16 MiB 未确认窗口、约每 256 KiB 累计确认，连续流水发送而不是每个窗口停等。测试前准备随机数据块并复用；TLS/QUIC/DTLS 数据通道不压缩，准备时间不计入吞吐计时，最终结果只计算接收端确认的字节。旧版对端回退原有 JSON/Base64 格式与限制。

QUIC 初始连接/流接收信用分别提高到 32/16 MiB；WebRTC 使用缓冲区低水位事件背压，不再每达到 256 KiB 就固定睡眠 10 ms。应用未确认窗口有界，但不等同于整个 Python 进程的内存上限。测速最长 120 秒，关闭会唤醒等待，失败/取消尽力清理远端测试状态。建议矩阵完成后测速；进行中的矩阵会产生额外网络流量并在结果中注明。

### 速度瓶颈判断

链路表新增“速度瓶颈 ↑ / ↓”，分别判断两个方向。选中链路后的详情保留中文解释及双端原始采样，选中链路摘要的悬停提示也显示原因；判定与采样持续写入本地日志并随原有日志队列上传服务器。

- **实现限制（疑似）**：发送端或接收端事件循环线程接近单核满载，或事件循环/pacing 唤醒严重延误。CPU 是整个事件循环线程的占用，不是所有核心的平均值，也不代表精确分离出了 Python 解释器、加密库和系统调用的成本。
- **方案/网络限制（疑似）**：双端实现负载低，观测到多次 QUIC 拥塞恢复、在途窗口接近用满、实测速率接近 `cwnd/RTT` 约束。它描述当前实现与当前 RTT/丢包条件的组合，**不证明任何 QUIC 实现都无法更快**。
- **正常**：双端负载低，并达到有效双端 WAN 参考/配置上限的 90%。没有参考时不以低 CPU 自动判定正常。
- **未确定**：不足一秒、双端采样不足、旧版对端不汇报、测速期间还有打洞/附件流量，或证据不能区分瓶颈。命名空间级 UDP 缓冲错误可能来自其他程序，不能单凭此计数判当前链路受限。历史测速保留“旧样本”，WAN 参考过期后不沿用“正常”标记。

每方向采集双端 CPU 时间、事件循环线程单核占用、50 ms 间隔的循环延迟、QUIC 数据报/定时器计数、窗口与 RTT、拥塞恢复次数下界以及 IPv4/IPv6 UDP 缓冲错误增量。采样数量有界，不开启逐包 qlog；不修改拥塞控制或 pacing 的内部状态。窗口指标是带版本保护的只读 aioquic 适配，库内部布局变化时缺失该证据，不阻断聊天或测速。

千兆链路建议选择 128 MiB 或更大做长样本确认；小包测速仍可用于快速检查，但不能据此可靠判断瓶颈。批量测速的流量会乘以链路数量和两个方向，测试前留意总流量。

QUIC 发送合并到下一轮事件循环，每累计约 256 KiB 主动让出执行，避免每块立即刷新与重复重建定时器。Linux 使用单个可复用的 `timerfd` 接收亚毫秒截止时间，无忙轮询；不支持或资源不足时回退 asyncio。仅在原打洞 socket 升级为 QUIC 后申请每方向 4 MiB 的内核缓冲区，日志记录内核实际值；平台可能截断或加倍这个值，客户端不会修改系统 `sysctl`。TLS/签名认证、MTU 证据、拥塞控制、有限应用窗口和接收确认保持不变。

IPv6 入站状态防火墙、IPv4 NAT、端口预测和网关放行通常是**建链方式**，不能仅凭方案名字判定建链后固有的速度上限。真实运营商限速、网关转发能力、路径 MTU、RTT、丢包以及所选传输实现都可能影响结果，需对照实验。当前 aioquic 后端仍未证明可跑满千兆，实测及复现命令见 `PERFORMANCE-AUDIT-2026-10-13.md`。

## 公网部署

默认开放服务器 **8443/TCP 和 8443/UDP**，不再需要 3478、3479。TCP 上共用 HTTP/WS 信令、日志和 TCP 映射观察，UDP 上提供标准 STUN；这是同一个端口号的两种协议，不是只开放 TCP。客户端的数据通道使用动态端口；是否能入站取决于实际 OS/CPE/运营商策略，不能由服务器开放端口保证。

只传 `--port 9000` 时，上述全部服务自动改用 **9000/TCP + 9000/UDP**。TCP 映射观察仍通过实际实验 socket 发起独立连接，不复用信令连接；TLS 模式使用同端口 HTTPS，保持证书和原域名校验。观察服务要求客户端直接连接 Python 服务端，不支持用 Nginx/CDN/反向代理代替实际 TCP 来源。

新客户端也兼容旧版服务端的独立端口。`v0.1.0` 旧客户端不能使用新版默认 HTTP 观察协议；暂不升级客户端时，服务端显式加 `--stun-port 3478 --tcp-port 3479`，并放行对应端口。单端口模式请使用新版客户端和服务端。

### socat / 内网端口映射

普通 socat TCP/UDP 转发重新建立连接，Python 端看到的来源通常是转发器，而不是客户端。信令和日志仍可使用，但不能把该来源及其端口视为客户端 TCP/STUN 映射，也不能向它回连来判断客户端 IPv4 入站。

这种部署请在服务端明确启用转发模式（同样适用于隐藏来源的反向代理）：

```bash
python server.py --port 8443 --forwarded --allow-inbound-check
# 单二进制版本：
./P2PLab-Server-linux-x64 --port 8443 --forwarded --allow-inbound-check
```

客户端填写公网入口，例如 `ws://实际域名:57878/ws`。转发模式不监听本站 UDP STUN，也不提供 TCP 映射或 IPv4 回连证据；客户端继续尝试公共 STUN、网关映射、局域网及 IPv6 P2P，日志上传和聊天功能不变。IPv6 回连仍由 Python 服务端直接发起，需要其自身有 IPv6 出口。两端都应升级；旧客户端不会识别转发模式。公网转发器仅凭来源地址无法自动识别，因此不能省略 `--forwarded`。

若采用保留客户端源地址的路由器 DNAT，只有外部端口与监听端口不同，可用 `--port 8443 --public-port 57878`：对客户端通告共享外部端口，但实际仍监听 8443/TCP+UDP。该参数不配置转发规则，也不修复 socat 丢失源地址；两个协议都必须映射。显式独立 `--stun-port` / `--tcp-port` 继续按原值通告。

客户端发现非公网信令来源时会保守禁用本站观察点（显式回环实验模式除外），并保留原始地址，标为“信令非公网/可能经转发”。明确启用 `--forwarded` 时，即使转发器来源本身是公网 IP，也会标为“信令转发器”并排除客户端公网出口冲突比较；多个真实公网观察地址不同仍显示“出口不一致”。HTTP 查询地址不会被用来伪造 TCP/UDP 映射或作为 IPv4 回连替代目标。

### 不使用 SSL/TLS 或 Nginx

可以直接启动；`--host` 默认就是 `0.0.0.0`，表示监听所有 IPv4 网卡。未传 `--cert`、`--key` 时提供明文 HTTP/WS，不需要 Nginx：

```bash
.venv/bin/python server.py --host 0.0.0.0 --port 8443
```

客户端配置 `server = "ws://实际服务器IPv4:8443/ws"`，然后启动：

```bash
.venv/bin/python client.py --config client.example.toml --allow-insecure
```

也可在 TOML 顶层设置 `allow_insecure = true`，无需每次传参数。`0.0.0.0` 只是服务器监听地址，不能填写为客户端连接目标。端口 8443 并不代表必须使用 TLS。

明文模式会在两端显示警告；信令、设备地址、准入 token 和上传日志没有传输加密，不能声称能抵御信令链路中间人。P2P 数据通道自身仍使用加密，但这不能替代可信的信令身份交换。此模式适合受控实验，公网长期运行建议启用 TLS。

### 直接使用 TLS

Python 服务端自身支持有效证书，同样不需要 Nginx：

```bash
.venv/bin/python server.py \
  --host 0.0.0.0 --port 8443 \
  --cert /absolute/path/fullchain.pem --key /absolute/path/privkey.pem \
  --token-file /absolute/path/access.token --data data/server
```

编辑 `client.example.toml`，设置 `server = "wss://实际域名或IPv4:8443/ws"`、`token_file` 和设备名，然后：

```bash
.venv/bin/python client.py --config client.example.toml
```

证书名称必须匹配连接目标；直接连接 IP 时证书需要相应 IP SAN。私有 CA 可以用配置中的 `ca_file`，没有关闭证书校验的选项。客户端信令连接强制使用 IPv4。远程明文 WS 默认拒绝；仅调试可显式 `--allow-insecure`，会暴露信令与设备地址，不能用于生产。

`--token-file` 是可选的服务器准入限制，公网部署强烈建议使用。房间号本身不是强认证口令；本工具信任信令服务器分配的对端身份，没有声称能够防御恶意信令服务器。设备 Ed25519 私钥自动保存在本地，入房挑战防重放；服务器持久绑定设备 ID 与公钥，不能只知道设备 ID 就替换连接。

### IPv6 入站回连验证

IPv4 服务器可以协调两端 IPv6 P2P，不需要自身有 IPv6。但 HTTP/TCP IPv6 回连实验需要服务器自身有可用的 IPv6 地址和出口路由；IPv4 信令监听 `0.0.0.0` 不妨碍服务端发起 IPv6 出站连接。没有 IPv6 出口的纯 IPv4 服务器无法执行这项检测。

回连功能默认关闭；管理员启用后，客户端入房就自动测试，**一个客户端也能测试，不需要等待第二个人**。客户端在本机 IPv6 地址上开启临时 HTTP 监听器，将地址、动态 TCP 端口和一次性校验 token 经信令提交；服务端直接向该 IPv6 地址发送 HTTP GET，验证 token 回显，将结果返给客户端。

例如在无 TLS 模式下启动（默认不限制公网 IPv6 前缀）：

```bash
.venv/bin/python server.py --host 0.0.0.0 --port 8443 \
  --allow-inbound-check
```

```bash
# TLS 模式同样只需在服务器参数后面加上：
--allow-inbound-check
```

回连目标必须为全局 IPv6、非特权端口；不设置 `--inbound-prefix` 时允许任意公网 IPv6，无需朋友先提供前缀。该参数现在只是可选限制：提供一个或多个前缀后才启用前缀白名单。服务端启动日志记录实际策略与前缀。回环、链路本地、ULA、组播、未指定地址仍不属于普通公网回连目标；回环仅供显式测试模式。每会话最多检测两个不同 IPv6 地址、每来源每分钟最多八次、全局并发两次。不跟重定向、不使用环境代理。客户端使用一次性 token 和短时监听器，服务端要求 token 回显；请求签名绑定当前信令会话，拒绝重复请求。

同一开关现在也允许每会话一次 IPv4 HTTP 回连，独立于两个 IPv6 名额。IPv4 目标只能是本次 WebSocket 连接实际观察到的来源地址，不能提交任意第三方 IPv4；回环仅在测试开关允许时可用。客户端绑定本地 IPv4，在 NAT 出口的同号端口接受直接回连；没有申请 UPnP 或借用 STUN/UDP 映射，因此回连失败不能直接证明 NAT 类型或所有入站均被阻断。监听本地地址、实际出口目标、端口和认证结果分别写入客户端与服务端日志。

回连选址使用完整网卡清单，不受 P2P 的 `max_addresses` 截断影响；同时存在合格稳定地址和合格临时地址时，两类各保留一个检测名额。每次监听前重新读取网卡，校验地址仍在原接口且状态、剩余有效期合格；临时地址轮换后重新选取当前地址。服务端请求仍最多两次，本地选址/监听失败最多重试八个不同地址。地址移除、DAD 状态或有效期导致的本地跳过记录为 `LOCAL_ADDRESS_NOT_AVAILABLE` / `NOT_TESTED`，不当成入站阻断。

客户端日志中的 `prefix` 给出网卡地址所属网段，仅在管理员选择限制前缀时需要用到。默认不限制前缀，稳定/临时地址和公网前缀变化均无需更新服务端白名单；客户端仍检查当前网卡地址状态和有效期。启用可选白名单后，匹配网段而非固定临时地址，公网前缀变化时需更新允许范围。`--inbound-prefix` 不会改变客户端地址或路由。

该基线检测会在 P2P 打洞及网关放行实验之前完成；客户端不会提前向观察服务器发起 IPv6 HTTP 连接，也不自动修改系统防火墙。检测完成就关闭临时监听器。

客户端终端输出监听地址和端口、HTTP 请求到达证据、结果码、耗时、系统错误号和 `firewall_assessment`；同样的信息保存在客户端日志并上传到中央日志。服务端也独立记录开始及结果。结果解读：

| 结果码 | 入站观察结论 |
|---|---|
| `REACHABLE` | 此次服务器到此客户端 TCP 端口的 HTTP 入站被允许，且已验证客户端响应 |
| `OBSERVER_NO_ROUTE` | 服务端无 IPv6 路由，无法判断客户端防火墙 |
| `TIMEOUT_INCONCLUSIVE` | 疑似丢弃，但路由故障、地址失效或链路丢包同样可能造成超时 |
| `CONNECTION_REFUSED` | TCP 被拒绝，可能是拒绝型防火墙或监听问题，不能单独归因 |
| `REJECTED_BY_POLICY` | 白名单、身份、重复请求或预算限制阻止了测试，不是防火墙结论 |
| `TOKEN_MISMATCH` | 收到 HTTP 响应但没有确认它来自该客户端监听器，不算成功 |
| `LOCAL_ADDRESS_NOT_AVAILABLE` | 本机地址已移除或不再适合新连接，未实际发起本次回连 |

没有可用全局 IPv6 或服务端未启用时明确显示 `NOT_TESTED`。所有结论只适用于本次观察源、地址、TCP 端口和时间，不是“整个入站防火墙关闭”的判定。

`--allow-loopback-check` 只供本机测试。没有全局地址、观察服务器无路由、超时、连接拒绝和 token 不一致分别记录。**TCP 回连可达不等于 UDP 可达；超时不能断言是客户端防火墙阻断。**

### RFC 5780 多观察点

服务器只有一个 IPv4 时，只能可靠报告对应目的地的映射观察。完整地址变化/端口变化实验需服务器实际拥有两个 IPv4：

```bash
--stun-host 第一个IPv4 --stun-port 3478 --stun-alt-ip 第二个IPv4
```

这是显式启用的高级多端口模式，需同时开放两个 IP 上的 UDP 3478、3479；省略 `--stun-port` 时使用 `--port` 及其加一端口。该功能生成四个观察端点，正确编码普通 `OTHER-ADDRESS`，不对它做 XOR。默认单端口模式不执行完整变端口/变地址分类，证据不足会如实报告。客户端还可配置最多三个额外 STUN 观察点；公共服务不支持 RFC 5780 时如实报告，不能据此完整分类 NAT。

默认公共观察点依次为 `stun.miwifi.com:3478`、`stun.cloudflare.com:3478`、`stun.l.google.com:19302`，可通过 `experiment.stun` 覆盖，空列表禁用公共观察点。公共服务的可达性取决于本机地址、运营商、DNS 和地址族，不保证国内任意网络可用。直连部署仍优先使用本站观察点；`--forwarded` 模式继续禁用本站观察点。

普通 UDP/QUIC 从实际打洞套接字逐个查询观察点，每个域名最多尝试两个解析地址，保留各次映射和失败证据。ICE 和端口碰撞后端先从当前选定的本机地址并发发送真实 STUN Binding 请求，选择有响应的观察点；成功选择缓存 120 秒，全部失败缓存 15 秒，地址或观察点变化使用独立缓存。可用性探测得到的映射不会当成实际打洞套接字的映射。aiortc/aioice 仅支持一个 IPv4 STUN 服务器，因此先实测选择再配置；IPv6 使用直接地址候选。原生 libnice 可按实验地址族选择观察点。全部不可达时仍保留直接候选，允许局域网、私网路由和 IPv6 实验继续。

失败结果和服务端日志保留本端/对端候选 IP 与端口、同套接字 STUN 记录、失败原因，以及 UDP 探测计数和套接字错误。缺少公网 UDP 候选会单独标明，不等同于已确认 NAT 类型或防火墙阻断。矩阵底部将网卡绑定地址与套接字候选分开显示。

## 实验覆盖与预算

默认选取最多四个本机地址、四组同地址族的两端地址组合。先完整读取网卡状态、过滤不适合新连接的地址，再分配名额：每个地址族优先选择有默认路由、路由代价较低的网卡；Windows 代价包含路由及接口 metric。保留可用全局 IPv6、IPv4，并在预算允许时同时保留稳定/临时 IPv6、兼顾其他网卡。虚拟网卡不会仅凭名称被排除，实际承担默认出口时同样优先。完整清单、路由选择依据和未入选原因都记录，候选数量有界而非无限穷举。每项都有独立 attempt ID、超时、结果及两端结果同步。

| 实验 | 参数变化 / 证据 |
|---|---|
| UDP | IPv4/IPv6；balanced、fast、staggered 三种发送/退避/错峰预设；错峰交换角色，其他预设不重复无效角色组合；每个实际来源独立挑战 |
| QUIC | 同一个打洞 socket 升级；默认完整尝试发送预设 × 1200/1400 payload × 两种角色，不再把这些参数绑在一起；证书固定与双向应用认证 |
| TCP + TLS | 两个拨号方向；TCP 自身的映射观察，不借用 UDP 映射；双向证书指纹固定 |
| TCP 同时打开 | 双端仅 bind/connect；默认 0、150、400 ms，各交换角色；扩展模式再加 50、1000 ms；没有 listen 兜底冒充成功 |
| WebRTC | 双栈、IPv4-only、IPv6-only，各交换发起角色；可靠 chat / benchmark DataChannel；丢弃 relay 候选 |
| 有界端口预测 | 同 socket 的重复、多目的样本；稳定、目的相关、可外推才尝试；最多四个预测端口，跨度不超过 32 |
| 网关放行 | UPnP IGD、PCP、NAT-PMP、IPv6 pinhole；交换 QUIC 角色；创建、续租、删除，然后重新验证 P2P 数据面 |

`--expanded` 增加 UDP/QUIC/TCP 的第二轮新套接字尝试，以及 TCP 同时打开的额外偏移。端口由内核分配，不保证关闭后的端口绝不复用。地址配对从对角线开始，在有限预算下兼顾双方的稳定/临时 IPv6，不让一端的第一地址占满所有组合。

基础矩阵上限为 200 项，完整实验矩阵上限为 1024 项，生成、分块信令和接收端同时校验。非 loopback 默认开启 `comprehensive = true`，loopback 默认仍用基础矩阵。超限时保留网关/ICE，按方法和地址对公平抽样；协调端完整记录省略参数，两端显示生成数、执行数与省略数。所有入选方案均继续执行，即使早已能聊天；不是无限扫描，也不保证穷举所有网络条件或提高到某个成功率。完整矩阵可能持续数十分钟或更久，不能把中途退出的未执行项算作失败。

矩阵最多并行 4 个尝试，按 IPv4/IPv6 与 UDP/TCP 分车道；同地址族、同传输类型的打洞仍串行，以避免映射/过滤探测和监听竞争互相污染。UPnP/PCP/NAT-PMP、端口池、NAT64 与原始报文研究任务独占运行，并等待当前尝试结束。一个方案等待对端结果时，其他独立车道可继续；超时会释放该尝试并报告缺少对端结果，独占任务超时期间仍会暂缓启动后续方案。日志记录启动车道、并发数和每项结果。不同车道并行仍会共享设备 CPU/接入链路，因此对精密吞吐对照应在矩阵结束后单独测速。

UDP 成功仅代表双向认证探测成功，不能直接聊天。STUN 成功只是观察。路由器返回租约只证明控制动作得到响应，不能证明公网可达或此次连接依赖该映射；这些证据分开保存。网关不支持时还会尝试对端辅助连接，但不会把“没有租约的 QUIC 成功”标成网关放行成功。

网关默认主动尝试，因为本实验的目的包含完整放行测试。配置 `gateway = false` 或 `--no-gateway` 可关闭。租期 120 秒、并发租约最多八个；禁止无限租约；正常退出尝试删除，失败明确记录剩余租期。UPnP 控制地址必须属于系统默认网关，禁止重定向/外部实体，不覆盖已占用的端口映射。

成功通道保留供 `/use` 比较，断线时选择存活的备用通道。信令暂时中断不会立即关闭已认证 P2P；服务端重连重新配对、改变会话身份后会重新建立实验。网络地址每 60 秒检查一次，变动时默认自动请求协调端重建矩阵，保留仍可用的通道，取消旧矩阵尚未完成的尝试并记录未执行数量。自动请求合并并设有 120 秒冷却；`auto_retry = false` 可关闭。不会仅因地址变为 deprecated 就强行关闭已建立的通道。这里是重新打洞和故障恢复，不冒称跨所有传输的无缝连接迁移。

### 完整实验机制

详细实施/验收边界见 [EXPERIMENT-COVERAGE.md](EXPERIMENT-COVERAGE.md)。新增 RTT/2 同步、TTL/Hop Limit 1/2/3 预热、0.5/2/5 秒错峰、TCP 同端口监听竞争和 STUNT #2 预热后反转；随机端口阵列 16/64/256 socket、单侧/双侧碰撞、四轮分段搜索、宽窗多公网 IP 预测；签名 LAN 广播/组播、自映射 hairpin；网关 UDP/TCP、A/B/双方申请、IGDv2 AddAnyPortMapping、PCP PEER/FILTER/PREFER_FAILURE；原生 ICE-TCP/UDP、uTP，以及 NAT64 跨地址族候选。

原生 ICE 使用系统 `libnice`，不配置 TURN；uTP 使用上游 `libutp`，可运行 `.venv/bin/python tools/install_libutp.py` 构建固定版本，或设置 `P2PLAB_LIBUTP=/absolute/path/libutp.so`。原生可靠流上仍有 TLS 和应用身份验证。缺库会记录“不适用/缺依赖”，不使用普通 UDP 伪造该后端成功。这里不实现 BitTorrent 节点/BEP 55 协议互操作，也不是把所有调研到的 VPN/DHT 产品都装作后端。

`raw_probes = true` 加入 ICMP 引用报文关联和 NATBlaster 序列号交换/SYNACK 注入的实际执行，要求 Linux `CAP_NET_RAW`。默认关闭并记录原因，客户端不自动提权、安装内核模块或修改防火墙。ICMP 回包、原始报文注入、最终 TLS/QUIC 通道是独立证据；UDP 连通但未见 ICMP 关联会标记 `connected-without-icmp-association`，不宣称 ICMP 生效。

NAT64 在 IPv6 端用 RFC 7050 的 `ipv4only.arpa` 两个已知 IPv4 地址发现前缀，支持 RFC 6052 的 /32、/40、/48、/56、/64、/96；也可明确配置 `nat64_prefixes`。通过同 socket 的 STUN 获取转换后 IPv4 映射，保留同 socket 建立 QUIC。IPv4 信令服务器仍需要 IPv6-only 客户端有 DNS64/NAT64 或 464XLAT 等可达路径；配置无法访问的 IPv4 字面地址不会自动变得可达。

## 网络诊断与 MTU

客户端采集 Linux 的 `ip -j address/route`、实际选路、接口 MTU、前缀、地址有效期与独立的 temporary/deprecated/tentative/dadfailed 标志；以 `(网卡, 地址)` 匹配状态，避免多网卡同地址混淆。`type`（stable/temporary）与 `state`（preferred/deprecated/tentative/dadfailed/invalid）独立保存。

`address_inventory` 保留完整的相关地址清单，包括未入选记录；`addresses` 是预算内候选，`excluded_addresses` 说明弃用、DAD、接口 down、过期、生命周期过短或预算限制等原因。DAD 未完成/失败、已过期、deprecated 地址不作为新连接候选；deprecated 记录仍保留，不把它误称为立即失效。首选期和有效期的剩余时长都须至少 30 秒，按采样单调时钟扣除已流逝时间，支持永久有效期表示。

HTTP 监听和使用指定源 IPv6 的 UDP/QUIC/TCP 新尝试前会再读网卡复查；原矩阵地址失效时该项明确标记本地地址不可用，重新 `/retry` 可协调新地址矩阵。psutil 提供回退枚举；Linux 需安装提供 `ip` 命令的 iproute2，结构化状态不可用时 IPv6 只保留为 `unverified` 诊断，不猜测它是稳定、可用于新连接的地址。所有采集只读、限时、有输出上限，不自动修改系统防火墙。不收集 MAC、Wi-Fi 密码或代理凭据。

**真实网络测试前请关闭两端的 VPN、代理和 TUN，避免测到代理出口。** 加入房间界面和客户端启动日志均显示此提醒；程序不自动改动网络设置。

国内适用的 HTTPS 查询包括 3322 / 花生壳 / IPW 的 IPv4，以及 IPW / 东北大学 NEU6 的 IPv6；同时独立查询 ipify / AWS CheckIP / icanhazip 作为补充。每次请求强制对应地址族、校验证书、禁用环境代理、拒绝重定向，只接收不超过 512 字节且符合指定格式的全局单播 IP，不能从登录页/广告页中随意提取地址。国内接口每次限时 4 秒，仅连接错误、超时和指定 5xx 最多重试一次；国外接口限时 3.5 秒、不重试。各接口并行执行，失败不会阻止其他结果或信令观察。保留每次请求的成功、失败、耗时及重试证据，不因为重试成功删除失败日志。

顶部及网络页区分 **HTTP 出口** 与 **交换服务器信令观察**，同一地址的不同来源不合并丢失；第三方查询全部失败仍可显示信令观察地址。多个接口返回不同地址时提示“出口不一致”，不按多数票选所谓真实 IP。IPv6 HTTP 出口与网卡清单不匹配时单独提示，绝不直接作为本机打洞候选。网络日志保留完整接口结果、多服务印证状态和来源对照；对端诊断信令仍限制 8 条观察，优先保留交换服务器来源，不扩大为任意数据通道。

系统级 VPN/TUN 仍可能接管请求，`trust_env=False` 不能绕过它，也不保证国内接口对每个运营商始终可达。HTTP 出口和信令观察都不是 UDP 映射；UDP 映射仍用同一个打洞 socket 测量。ping、tracepath 和系统路由仅提供额外证据，不把超时解释成确定的防火墙结论。

`--no-external-diagnostics` 同时关闭公共 HTTP 查询、外部系统探测和额外公共 STUN，仍保留本机系统快照与自有服务器 STUN。Linux 之外的系统路由/网关提取和终端兼容性尚未实机验收，不冒称全平台支持。

UDP 握手使用 512 字节 payload。认证后，按方向各重复验证 512、900、1200、1400 字节；大包失败后复查小包，记录 `EMSGSIZE` 和疑似尺寸黑洞，不把丢包直接当成 PMTU 结论。Linux 显式禁止探测包静默分片。

这是一套有界的 DPLPMTUD 思路实验，**不是完整 RFC 8899 实现或 PMTU 认证**。QUIC 不降到 1200 以下；1400 未确认时可明确标记原参数失败，再降到已确认的 1200。没有 1200 的方向证据时，该 QUIC 尝试失败，其他方案照常继续。

## 中心日志

客户端 `data/client/client.sqlite3` 是持久上传队列，服务器 `data/server/central.sqlite3` 是中心库。SQLite WAL + FULL synchronous；客户端先提交事件，服务器提交后回 ACK。丢 ACK 会重传，服务器按事件 UUID 去重。断线记录保留，下次使用**同一数据目录和设备密钥**启动会补传，不淘汰未确认事件。

日志正文逐条以 zlib 无损压缩 BLOB 落盘，上传使用 `zlib-json-v1` 压缩整个批次。默认每 5 秒最多发送一批 1024 条（原文最多约 2 MB，压缩数据最多 200 KB），未确认时每 10 秒重试；不能压缩的小概率大批次会自动缩小批量，不删除条目。可在客户端 `[logs]` 调整 `upload_interval`（0.1–60 秒）、`retry_interval`（不小于上传间隔，最多 120 秒）和 `batch_events`（1–1024）。正常上传降频，退出时仍有限快速补传；积压超出上传吞吐时在磁盘排队，不截断。握手协商格式，新服务端兼容旧客户端；连接旧服务端时客户端明确记录退回未压缩小批次，建议两端一起升级。

已有数据库第一次升级启动时分事务压缩旧记录，保留事件数量、UUID、游标、ACK、设备标识及全部字段；完成后自动 VACUUM 回收空页。迁移中断可继续，**升级前应停止所有写入该库的旧进程，并预留数据库/WAL及 VACUUM 临时空间**。TUI 的搜索、翻页、详情、分片重组保持不变。直接 SQL 读取 `document` 现在会得到 BLOB；推荐用导出接口，或 Python `p2plab.logcodec.load_document()` 解码（也支持旧 TEXT）。压缩不是加密，数据库权限仍为 0600。

记录所有应用诊断、状态、参数、异常堆栈、网络结果和终端命令；接入 Python 日志及 asyncio 异常。聊天正文、图片/文件内容、测速字节、设备私钥、token、签名和 SDP 凭据不进入中心库，聊天只保存消息 ID、长度、路径和送达统计；附件保存名称、大小、进度、校验值和保存路径等元数据。实际 IP、路由、房间、设备标识及文件名/路径属于敏感诊断信息，中心库应严格限权。

超过 64 KB 的单条事件按 `journal.fragment` 无损分块，避免大日志堵住整个上传队列。按 `fields.original_id` 分组、按 `fields.index` 排序后拼接 `fields.json_part`，再解析 JSON 即可恢复原事件；`fields.parts` 给出完整块数。脱敏在分块前完成。

服务器首次启动生成 `data/server/admin.token`，文件权限 0600，不打印 token 内容。导出：

```bash
.venv/bin/python export_logs.py \
  --server http://127.0.0.1:8443 \
  --token-file data/server/admin.token \
  --room 1001 --output data/room-1001.jsonl.gz
```

TLS 服务用 HTTPS，可加 `--ca-file`；明文服务将导出地址改为 `http://实际服务器IPv4:8443`，但准入凭据和导出的日志同样没有传输加密。支持 `--client` 筛选、`--after` 游标增量；不公开无鉴权日志接口。服务器自身日志也有统一房间字段，可与客户端事件对齐。时间为 UTC ISO-8601，RTT/耗时使用单调时钟。

导出 HTTP 响应按请求头协商压缩，下载工具默认保存 `data/export.jsonl.gz`；`.gz` 后缀压缩 JSONL，显式 `.jsonl` 仍保存原文。`--after` 可追加 gzip 成员，标准 gzip 解压后保留所有事件及游标。

不设置会静默丢旧日志的轮转。请监控剩余磁盘并安排中心库备份；**网络断开时只能延迟上传，磁盘损坏/写满/断电不能承诺绝对零丢失**。程序关闭最后有限等待上传，未确认记录留在本地。关闭日志传输的信令不影响已经建立的数据通道，但以后重新配对需要信令服务。
